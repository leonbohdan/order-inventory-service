## 🔍 Завдання 1: Експерименти з PostgreSQL та EXPLAIN ANALYZE

### Мета

Навчитися читати плани виконання запитів і бачити різницю між послідовним скануванням та використанням індексів.

### Кроки

1. **Генерація великого обсягу даних:**
   Утилітою SQL згенеруй 200,000 записів у таблицю `orders` (через pgAdmin або CLI):

   ```sql
   INSERT INTO "Order" ("id", "userId", "status", "totalAmount", "createdAt")
   SELECT
     gen_random_uuid(),
     (SELECT "id" FROM "User" ORDER BY random() LIMIT 1),
     (ARRAY['PENDING', 'PAID', 'SHIPPED', 'CANCELLED'])[floor(random() * 4 + 1)],
     floor(random() * 10000 + 100)::int,
     NOW() - (random() * (interval '90 days'))
   FROM generate_series(1, 200000);
   ```

2. **Аналіз вихідного запиту:**
   Виконай запит без індексів:

   ```sql
   EXPLAIN (ANALYZE, BUFFERS)
   SELECT * FROM "Order"
   WHERE "status" = 'PAID' AND "createdAt" >= NOW() - INTERVAL '7 days'
   ORDER BY "createdAt" DESC;
   ```

   Зверни увагу на:
   - Тип сканування (`Seq Scan`);
   - Кількість прочитаних сторінок (`Buffers: shared hit/read`);
   - Загальний час (`Execution Time`).

## ⚡ Завдання 2: Проєктування та накатка індексів

### Мета

Оптимізувати запити за допомогою правильних B-Tree індексів через Prisma або TypeORM.

### Кроки

1. **Складений індекс (Composite Index):**
   - Додай складений індекс на поля `(status, createdAt)` або `(userId, createdAt)` у схемі ORM.
   - Згенеруй і застосуй міграцію.
   - Повторно запусти `EXPLAIN (ANALYZE, BUFFERS)`.
   - Зафіксуй зміну: чи з'явився `Index Scan` або `Bitmap Index Scan`? Як змінився Execution Time?
2. **Перевірка правила лівого префікса (Leftmost Prefix Rule):**
   - Запусти запит, який фільтрує лише за `createdAt`, коли індекс створено як `(status, createdAt)`.
   - Поясни, чому індекс може ігноруватися базою даних у цьому випадку.
3. **Частковий індекс (Partial Index):**
   - Створи індекс, який зберігає записи тільки для замовлень зі статусом `PENDING` (наприклад, для черги необроблених замовлень):

     ```sql
     CREATE INDEX idx_orders_pending ON "Order" ("createdAt") WHERE "status" = 'PENDING';
     ```

   - Порівняй розмір такого індексу з повним індексом.
